## [Unreleased]

### Added
- **Bundle format 2: the `n8n_files` volume travels in the backup** (PROD-PLAN D-19), as an optional `n8n-files.tar.gz` built from a new read-only mount on the `backup` service. It is deliberately skippable — over `BACKUP_FILES_MAX_MB` (128), short of scratch space in the RAM-backed tmpfs, or unreadable by the backup container, and the member is left out with a warning while the database backup still succeeds, because the database is what a backup exists for. Every skip records its reason in the manifest (`n8n_files: {included, reason}`) and sets the new `backup_last_files_included` metric, which `make doctor` reports, so a tree cannot quietly stop being backed up. `make restore` extracts it while n8n is stopped and after the database swap, through the new `compose/scripts/files-restore.sh` (a throw-away root container, as `files-perms.sh` does it, because the tree is uid 1000 and the backup service runs as uid 70); it **merges** rather than wiping, so files the bundle does not carry are left alone. `unpack_bundle` now verifies **every** member the manifest lists rather than a fixed pair: format-1 bundles verify exactly as before, a newer-format bundle warns instead of being refused (the disaster-recovery case of an old checkout and a current bundle), and a swapped or truncated member is still refused. `n8n_data` stays out on purpose — community packages return via `N8N_REINSTALL_MISSING_PACKAGES=true`, and a restore deliberately deletes the cached settings file. Two limits are documented rather than hidden: the tree is tarred while n8n runs, so a file being written is captured half-written, and a restored tree can be older in some places than others. New keys: `BACKUP_INCLUDE_FILES`, `BACKUP_FILES_MAX_MB`.
- `make rotate-recovery-key` (PROD-PLAN D-17, closing the gap recorded in HANDOFF §5): replaces the offline age recovery key, which `make init FORCE=1` deliberately refuses to do because it keeps a detached key’s public half. It generates a new pair, shows it once, makes you paste it back from the password manager **before** `.env` is touched (so a truncated copy is caught while the original still exists), swaps the public half in, and records `BACKUP_AGE_RECOVERY_ROTATED_AT`. Rotation cannot re-encrypt bundles that already exist — they still need the OLD key — so it counts them and says to keep that password-manager entry until they leave retention. `KEEP_OLD=1` additionally keeps the previous public key as a recipient on new bundles (`BACKUP_AGE_RECOVERY_PUBLIC_KEY_PREVIOUS`), which is for a key you **lost**: it is off by default, because rotating a key that *leaked* must not encrypt the next backup to it. `make doctor` reports the rotation, warns while `KEEP_OLD` is in force, and **fails when the running backup sidecar holds a different recovery key than `.env`** — the trap of rotating without `make up`, since the sidecar keeps the environment it was created with. `make preflight` refuses a malformed or duplicate previous key.
- `scripts/new-dev-vm.sh`: a fresh Ubuntu 26.04/24.04 VM to a kit dev host in one run — base packages, clone, `bootstrap-host.sh`, the dev tools at CI's pins (shellcheck, hadolint sha256-checked; yamllint, age, mkdocs, gh), then `dev-host-catchup.sh` under `sg docker` so no log-out is needed.
- `scripts/dev-host-catchup.sh`: brings a dev/test host that fell behind (or a fresh clone) up to the repository's state — fast-forward pull, `make init` when needed, `make upgrade` when the pin is newer, the monitoring profile (with ≥ 4 vCPU), Telegram and R2 settings at hidden prompts when missing, `make up`, proof of what it configured, the recovery-key detach, then status, doctor and smoke. `--check` is read-only.
- `N8N_STOP_GRACE_PERIOD` (`.env`, default 40): Docker's stop window for every n8n container, generated workers included. `make doctor` measures the p99 execution duration of the last 7 days and warns when it reaches `N8N_GRACEFUL_SHUTDOWN_TIMEOUT` (PROD-PLAN D-2).

### Changed
- n8n 2.42.6 → **2.44.6** (+ `n8nio/runners:2.44.6`): two minor releases with **24 database migrations** between them, so a `make rollback` of this upgrade takes the restore path and loses what was written after the pre-upgrade backup — not the images-only path the 2.42.x moves took. Counted over both folders n8n applies (all of `common/` plus the dialect's own), with the method cross-checked against this repository's own recorded figures: it reproduces the 11 migrations CI measured for the 2.41.7 → 2.42.x drill, where counting only `postgresdb/` gives 1. No breaking changes to any setting the kit uses; the 2.43 and 2.44 notes rename and remove nothing in the `N8N_*`, `EXECUTIONS_*`, `QUEUE_*` or `DB_*` families. CI's upgrade drill moves to **2.43.8 → pin** (10 migrations), the newest stable patch of the previous minor — one minor, which is the hop a user actually makes. One fix in the span acts on a known issue: per-process crash-journal paths (n8n #37670, in 2.44.0), the shared `/home/node/.n8n` journal that made a starting process log "Last session crashed" (HANDOFF §5) — taking effect needs a kit change, not just the pin. The worker-shutdown fixes in the same span (#40086, #40162, #40050) return jobs that were **dequeued or prefetched** to the queue, which is not the same thing as an execution already running, so they do not by themselves change the kit's measured finding that a killed worker loses its in-flight work (PROD-PLAN D-14).
- n8n 2.42.4 → **2.42.6** (+ `n8nio/runners:2.42.6`): two patch releases, no database migrations; tested by CI's upgrade drill (2.41.7 → 2.42.6, rollback, upgrade) and, on 2026-10-09, upgraded and rolled back (images only) on the build VM (PROD-PLAN D-14).
- **`EXECUTIONS_TIMEOUT` now ships as `3600` (one hour) instead of n8n’s `-1`** (PROD-PLAN D-11). Nothing in the stack ends a hung execution by itself: with no ceiling it keeps one of a worker’s concurrency slots until that worker is restarted. A workflow may still set its own limit, but only up to `EXECUTIONS_TIMEOUT_MAX`, which stays `3600` so one workflow cannot opt out of the ceiling — raising that is the deliberate way to allow a long job. `make doctor` now reports the limit beside the p99 it already measures and warns when it is `-1`, is not a number, or is at or below that p99 (it is then cutting work that normally finishes); `make preflight` warns when the timeout exceeds the per-workflow maximum. **Existing hosts are unaffected** — `.env` is never rewritten, so every stack created before this keeps `-1` until its operator changes it, which is what the doctor warning is for.

### Fixed
- CI: `caddy` and `postgres` now come from `mirror.gcr.io/library/*` instead of `public.ecr.aws/docker/library/*`. ECR Public's anonymous limit is a **data** limit, not a pull count, and it is shared across GitHub's runner IPs — `toomanyrequests: Data limit exceeded` kept failing `smoke` and `upgrade` on changes that touch neither, and held four PRs for a day with re-runs failing the same way. The digests in `compose/versions.env` stay authoritative (both were checked against the mirror before the switch), so a mirror that ever diverged fails the pull rather than running a different image.
- Smoke 09 failed on any stack idle for more than an hour: an idle n8n writes almost no logs, and the Loki check looked back a fixed hour. It now looks back to the newest line Docker holds for any n8n container (at least 1 h).
- `make upgrade` no longer warns `UPDATED … the tag was re-pushed or the version changed` about the n8n and runners digests it moves on purpose; `pin.sh` reports them as `[ OK ] N8N: <old> -> <new>`. A digest that changes at the same version (a re-pushed tag) still warns.
- `make doctor` no longer warns about cAdvisor after a busy reboot when every restart was its startup watchdog doing its job (checked against the watchdog's own log lines); any other restart still warns.
- Raising `N8N_GRACEFUL_SHUTDOWN_TIMEOUT` above 30 s had no effect: the 40 s `stop_grace_period` was hard-coded, so Docker killed the worker first. Preflight and doctor now refuse a stop window shorter than the timeout + 10 s.
- Monitoring: after a busy host reboot cAdvisor could start before dockerd answered, lose its Docker integration for good and keep reporting "healthy" without any container labels (blind per-container panels and alerts). A startup watchdog now restarts it until the integration registers.

### Security
- `make detach-recovery-key` says on screen that it shows the secret itself and reminds you to clear the scrollback afterwards; runbook C4 adds the step. On the build VM a detach screen was pasted into a chat right after the key had been stored safely.

### Fixed
- The Read/Write Files node could not write anything (2026-10-10): `/home/node/.n8n-files` does not exist in the n8n image, so Docker created the `n8n_files` mount point as root:root while n8n runs as uid 1000, and every write failed with EACCES on a fresh install. `make up` now runs `scripts/files-perms.sh`, which chowns the volume to 1000 once, after `compose up`, from a throw-away root container.
- `make preflight` / `make doctor` (2026-10-10): the disk check no longer invents a "0 GB free" failure when the docker daemon is unreachable — seen on a host with 83 GB free, where it fired underneath the real docker error. `$(docker info … || echo /var/lib/docker)` captured docker info's empty line *and* the fallback, leaving `df` an unusable path; under `pipefail` the trailing `|| echo 0` then appended a literal `0`, turning "unreadable" into a confident wrong number. The default now applies to the captured value, an unreadable path is reported as such with the `df -h` command to run by hand, and a path assumed because the daemon is down says so.
- S7 review (2026-10-09, 41 confirmed findings): a closed SSH session no longer stops make upgrade/rollback half-way (EIO under `set -e`); an aborted attempt keeps the last rollback point; make rollback can no longer strand the stack (fetch before stop, fallback targets, ABORT=1, decision recorded only when committed); autovacuum no longer counts as an n8n session; restore's safety bundle carries the right version; pin.sh resolves ghcr.io through its registry fallback (GET for the auth challenge).
- Monitoring review (2026-10-09, 41 confirmed findings): Telegram alerts are plain text (Grafana's default HTML mode made Telegram reject any alert text with "<…>"); Grafana memory (its own gzip ballooned the heap to ~1 GiB: `GF_SERVER_ENABLE_GZIP=false` behind Caddy's compression, `GOMEMLIMIT`, unused data-source plugins off); cAdvisor `disk`/`diskIO` metrics off (60 % CPU on a busy host); Grafana first-start window 5 min; 17 alert rules (new: KitServiceUnhealthy for Postgres/Valkey/any kit container, WebhookProcessorMissing, WorkerPoolDown, CertCheckFailing; BackupMissing/RestoreTestStale count from when backups were switched on; ExecutionFailureRate counts first observations; DiskHigh watches every filesystem); dashboard fixes (TLS panel, CPU stack, load per CPU, pool up/down, disk I/O, sparse series, CPU by project, memory % of limit); `make kuma-setup`; smoke 09 checks isolation, Loki redaction, Telegram mode and the Kuma admin; the alert drill also tests WorkerPoolDown; ContainerMemoryPressure + ContainerOOMKilled alerts (19 rules); `make up` reloads Grafana's provisioning (rule changes no longer need a Grafana restart).
- Backup/restore review (2026-10-08, 28 findings): `make restore` restores into a staging database and swaps it in atomically (a failed pg_restore no longer leaves an empty database), checks the encryption key before the safety backup and stops n8n before it, resets n8n's cached key file after a restore (the new-host `ADOPT_KEY` procedure left n8n unstartable), and empties the decrypted work volume on every exit; `latest` ignores safety copies and future-dated names and refuses when a remote cannot be listed; every bundle name is bound to its manifest; backups alert and set `backup_last_status 0` on ANY failure; retention validates its values, never deletes the newest 7 per directory and prunes by the UTC name; monthly copies are self-healing; one lock across all backup containers; manifest counts come from the dump itself; `BACKUP_REMOTES` / `BACKUP_LOCAL_PATH` / retention / memory-vs-tmpfs are validated by preflight; doctor FAILs on a failed last attempt and checks the recovery key; the restore test verifies every remote's newest bundle and its age; `N8N_REINSTALL_MISSING_PACKAGES=true`. New defaults: `BACKUP_TMPFS_SIZE=1g`, `MEM_LIMIT_BACKUP=1536m`. New: `BACKUP_RETENTION_MIN_KEEP`, `BACKUP_ALLOW_SINGLE_RECIPIENT`, `RESTORE_TEST_MAX_AGE_HOURS`, `make restore-clean`, CI disaster-recovery drill (`tests/ci/dr-drill.sh`).
- n8n-main crashed with `EACCES mkdir /home/node/.cache/n8n` after any container restart (Docker mounts a tmpfs on a directory missing from the image as root 0755 after a restart); the tmpfs mounts now carry uid/gid/mode (S5).
